== Architecture Notes ==
- svelte.config.js uses adapter-cloudflare (not adapter-node)
- Supabase clients use lazy initialization (getSupabase/getSupabaseAdmin) to avoid build-time crashes
- wrangler.toml must include pages_build_output_dir and nodejs_compat flag
- Frontend env vars: PUBLIC_SUPABASE_URL, PUBLIC_SUPABASE_ANON_KEY, PRIVATE_SUPABASE_SERVICE_KEY
- Ingest env vars: SUPABASE_URL, SUPABASE_SERVICE_KEY, REDIS_URL
- signals_1min is a materialized view refreshed by worker (not TimescaleDB continuous aggregate)
- Auth uses Supabase Auth with @supabase/ssr for cookie-based sessions on Cloudflare Pages
- Stripe billing: Pro ($19/mo), Team ($49/mo) - products created in Stripe dashboard
- Admin access: is_admin flag on users table, no role-based system

US-181: DONE - The alert worker was silently losing outage alerts. drainAlerts read a batch with

-- Phase 25: Platform Improvement Loop (iteration 13/15) --
US-182: DONE - Redis was configured to throw away the queues, and a failed queue write was
  reported as success.
  (1) docker-compose ran Redis with --maxmemory-policy allkeys-lru. But Redis here is purely a
      queue: an audit of every call site found only lmove, lrem, rpush and list pipelines — no
      GET/SET/EXPIRE, no cache keys at all. There was nothing cacheable to evict, only accepted-
      but-undelivered customer data. And memory pressure arrives exactly during a large outage,
      when many APIs fail at once and the alert queue is at its longest, so the alerts would be
      evicted at the moment they matter most. This also silently defeated the claim-then-ack
      protocol from US-181, which cannot survive the queue key itself being evicted.
      Now noeviction, with maxmemory a configurable 512mb default.
  (2) ioredis pipeline.exec() resolves to per-command [error, result] pairs and does NOT reject.
      The ingest route's bare `await pipeline.exec()` therefore treated a full or read-only
      Redis as success and answered 202 for signals that were never queued. It now checks the
      result and returns 503. The worker's re-queue path — added by the author specifically so
      signals "aren't lost" — had the same unchecked exec, and now logs the loss explicitly.
  New services/ingest/src/lib/redis-results.js (13 tests) plus a guard test that fails if an
  evicting policy is reintroduced or a queue pipeline is awaited without inspecting the result.
  Mutation-checked on both halves.
